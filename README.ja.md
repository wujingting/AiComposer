# AI 構図アシスタント

[English](README.md) | [中文](README.zh-CN.md) | **日本語**

端末上で動く撮影ガイドです。画面を見て、構図・光・ピントのどこに問題があり、どう直せばよいかを伝え、AI 美的評価モデル（CLIP + LAION）で採点します。すべてスマホや PC 上でオフラインで動きます。

| 製品 | 内容 | 用途 |
|---|---|---|
| **AI構図アシスタント**（`app-sony`） | Wi-Fi でソニー a6000 に接続する Android アプリ：リアルタイムのガイド、設定の提案、ワンタップ適用、自動シャッター | ソニーのカメラで撮影 |
| **AI構図（スマホ）**（`app-phone`） | スマホ自身のカメラで同じリアルタイムのガイド | スマホで撮影 |
| **AI写真採点**（`app-score`） | 撮影済みの写真を採点し、セレクトと類似写真を表示、1 枚ずつ解説してトリミングを提案 | スマホでの写真選び・編集 |
| **PC 用セレクトツール**（`tools/photo_picker`） | フォルダー全体を採点（JPG + ソニー ARW）し、連写の重複を除いて良い写真をコピーする Python ツール | PC での撮影データの整理 |

3 つのアプリは 1 つのライブラリ（`core`）を共有しています：同じルール、AI モデル、画面部品を使うので、そこでバグを直せばすべてのアプリに反映されます。PC 用セレクトツールも同じ AI モデルと採点方法を使います。

表示言語はシステムの言語に従います：中国語、日本語、それ以外はすべて英語。アプリは横向き・縦向きどちらでも使え、システムの自動回転の設定に従います。

以下では、まずソニーカメラ版を詳しく説明し（撮影ガイドエンジン、AI モデル、画面構成の多くはスマホ版にも当てはまります）、その後ほかの製品を紹介します。

## 機能（ソニーカメラ版）
| 機能 | 説明 |
|---|---|
| ライブビュー | ソニー Camera Remote API のライブビューストリーム |
| 三分割線 + 構図スコア | 被写体と最寄りの三分割交点の距離、端への接触、頭上の余白、水平線から 0〜100 点で総合評価 |
| 被写体検出 | ML Kit の顔検出 + 物体検出（オフライン）。黄色の枠 = 顔、水色の枠 = 物体、太い枠 = 主被写体 |
| 構図のヒント | 「人物を三分割の交点へ：カメラを右に振る、下に向ける」 |
| 水準器 | 画面内の水平線を自動で見つけ、傾きを表示 |
| シーン判定 | ポートレート／風景／夜景／動体／クローズアップ／スナップ |
| 設定の提案 | 絞り、シャッター、ISO、露出補正 + 理由（逆光、白飛び、手ブレ、動体） |
| ワンタップ適用 | 提案した設定をカメラに書き込み（モードダイヤルによる制限あり、後述） |
| **AI 美的評価** | CLIP ViT-B/32 + LAION 美的評価ヘッド、約 1 秒に 1 回 |
| **AI シーン判定** | 同じ CLIP 特徴量でゼロショット分類。ルールより正確（動体・暗所は引き続きルールで判定） |
| **AI 構図** | タップしたときのライブビューから構図の見本を表示します。通常モードでは 19 個の候補を比較し、トリミングによる改善が小さい場合は元の構図を使います。トリミングを提案するときは紫の破線枠を一時表示します |
| **トリミング前提** | 焦点距離が足りないとき、後でトリミングする割合と仕上がりの縦横比を設定。構図は白枠（仕上がり範囲）で評価し、安全シャッター速度と ISO 上限も自動で厳しくなります |
| 自動シャッター | 総合スコア（構図ルール + 美的評価）が約 0.75 秒続けて基準を超えると撮影。間隔は 4 秒以上 |
| **方向矢印** | ライブビューの端に黄色の大きな矢印でカメラを向ける方向を表示。構図が決まると短く 1 回振動（最大 4 秒に 1 回） |

## 画面構成
- **横向き**：左にライブビュー、右にパネル。**縦向き**：上にライブビュー、下にパネル。
- パネルは上から順に：
  1. **ヒント欄**：大きな総合スコア（シーン付き）+ 重要な問題 3 件の短い一言（例：「人物が左端で切れている」）。それぞれ重要度の色バー付き。高さが固定なので、内容が変わっても下のボタンは動きません。詳しいアドバイスはチェックリストにあります。
  2. **「ガイド」タブ**：チェックリスト、おすすめ設定、カメラの現在値、AI 美的評価。リアルタイムに変化します。
  3. **「設定」タブ**：自動シャッターの基準、レンズの焦点距離、トリミング前提、無視中のルール。
  4. **下部の操作バー**（位置固定）：撮影／提案を適用／AI 構図、自動シャッターのスイッチ、接続／切断。
- ソニー版でもスマホ版でも参考画像は固定されるので、カメラやスマホを動かしながらライブビューと見比べられます。「AI 構図」をもう一度タップすると今の画面で更新でき、閉じるボタンで非表示にできます。
- ライブビューには三分割線、検出枠、水準器、方向矢印を表示します。詳しいアドバイスはガイドパネルで確認できます。
- 屋外向けの設計：大きな文字、写真の色の判断を邪魔しないニュートラルなグレーの背景、強調色は 1 色だけ：**黄色 = やること**（メインのボタン、選択中の項目、矢印）。緑／オレンジ／赤 = 良い／注意／問題。3 つのアプリで同じ配色と文字サイズを使います（`core/ui/Theme.kt`）。

## ビルドと実行（初回）
1. **Android Studio** をインストール（Windows／Mac どちらでも可）。初回起動時にウィザードで SDK を入れます。
2. File → Open → `AiComposer` フォルダーを選択 → 右下の Gradle 同期が終わるまで待ちます（初回は依存関係のダウンロードで 10〜30 分、ネット接続が必要）。
   - 「Upgrade Android Gradle Plugin」と出たら、**ひとまずアップグレードしない**を選択。
   - SDK 35 がないと言われたら、メッセージ内のリンクからインストール。
   - **Gradle JDK は JDK 21 を選択**（Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK）。最近の Android Studio に同梱の JDK は 25 で、Gradle 8.11 は対応していません。
3. Build → **Make Project** を実行し、下部の Build ウィンドウに赤いエラーがないか確認。
4. スマホで「開発者向けオプション → USB デバッグ」を有効にし、USB ケーブルで PC に接続。上部でスマホを選び、▶ の左の実行構成でインストールするアプリ（**app-sony** = ソニーカメラ版、**app-phone** = スマホカメラ版、**app-score** = 写真採点アプリ）を選んで ▶ Run。
5. 単体テスト：コマンドラインで `gradlew.bat test`（Mac は `./gradlew test`）、または Android Studio で `core/src/test` を右クリック → Run Tests（Gradle で実行）。

### ビルドエラーが出たとき
Build ウィンドウの**最初の赤いエラー**（ファイル名と行番号がある行と、その下の数行）をコピーしてください。
1 つ直すと後続のエラーがまとめて消えることが多いので、毎回最初の数件だけ見れば十分です。

## 撮影ガイドエンジン（ルール集）
`coach/` に約 45 のルールがあり、いくつかの分類に分かれています。どのルールも「何が問題か + どう直すか」を示します：

| 分類 | ルール |
|---|---|
| 構図 | 被写体の位置（三分割の交点／対称・日の丸構図を判別）、被写体の切れ、被写体の大きさ、視線・進行方向の余白、串刺し、背景のごちゃつき、被写体の際立ち、端の邪魔もの、画面のバランス、水平 |
| 光・露出 | 全体が暗すぎ／明るすぎ（シャッター → 絞り → ISO の順にどのダイヤルを回すか案内。安全シャッター速度と ISO 上限を守る）、逆光、白飛び・黒つぶれ、顔の白飛び、明暗差が大きすぎ（DRO／HDR）、硬い光・トップライト、ホワイトバランスとミックス光、雪・砂浜、暗所 |
| ピント・設定 | シャッター速度は十分か、ISO ノイズ、被写界深度（顔の大きさから距離を推定、集合写真は前後の深度も計算）、被写体にピントが合っているか、手ブレ、フォーカスモード、トリミング後の画素数 |
| ポートレート | 目つぶり、表情、頭上の余白、目を上の三分割線に、関節での切れ（姿勢検出）、近距離での顔のゆがみ、頭の傾き |
| 風景・建築 | 地平線が真ん中、空の割合、前景が空っぽ、縦線の傾き・あおりによる収束 |
| スナップ | 文字の切れ、文字の傾き、主役がない（同じくらい目立つものが複数）、もっと近づく、色とコントラストが平坦。光と影、導線、シャッターチャンス、動物、視点などのヒント |
| 美しさ | CLIP 美的評価 |

- 重要度：問題（−25）> 注意（−12）> 参考（−4）> ヒント（減点なし）> ✓
- 項目スコア = 100 × e^(−その項目の減点/60)。**構図／光／技術**の 3 項目
- 総合 = 3 項目の加重平均（構図 50%、光 25%、技術 25%）。美的評価モデルがあれば 6:4 で混ぜ、目つぶりやブレなど致命的な問題があれば最大 60 点。重みは `coach_config.json` の `total.*`
- **原因ごとのグループ化**：同じ原因による問題は 1 回だけ減点（例：「背景のごちゃつき」「被写体の際立ち」「被写体が小さい」は 1 グループ）。他は「同じ原因」と表示
- **時間的な平滑化**：直近 1.5 秒の 60% 以上で出た問題だけを表示し、30% 未満になるまで消さないので、ヒントがちらつきません
- **自動シャッター**：構図スコア（+ 美的評価）で判断。その瞬間に人物や技術面の「問題」（目つぶり、ブレ、被写界深度不足）があれば撮らず、光の問題では止めません（後処理で救えるため）
- ヒント欄には重要な 3 件だけを短い一言で、「ガイド」タブのチェックリストには全件と詳しいアドバイスを表示
- ルールの追加：`coach/*Rules.kt` に `Rule` を書いて `all` リストに追加。表示する文字は `tr(中国語, 日本語, 英語)` で 3 言語とも書き、ヒント欄用の短い一言 `short` も 3 言語で書きます

### しきい値の調整（再ビルド不要）
しきい値はすべて設定ファイルにあります。アプリの初回起動時にスマホへ書き出されます：
`Android/data/com.example.aicomposer/files/coach_config.json`
USB 経由またはスマホのファイルマネージャーで編集し、**アプリを再起動すると反映**されます。各項目の意味は `coach/CoachConfig.kt` のコメントを参照。
ファイルを削除して再起動すると、デフォルト値に戻ります。
ルールのしきい値のほか、`ai.threads`（美的評価モデルの CPU スレッド数、既定 2。多いほど速いが発熱も増える）と、方向矢印・振動用の `guide.*` もあります。

### ルールの衝突と「意図的」
- ルール同士が逆方向の移動を提案することがあります（例：三分割法は左へ、視線の余白は右へ）。エンジンは優先順位で 1 つだけ残します：
  視線・進行方向の余白 > 頭上の余白 > 関節での切れ > 被写体の切れ > 目の位置 > 三分割の交点。譲った側は「ヒント」に格下げされ、減点されません。
- チェックリストの各問題には「意図的」ボタンがあり、押すと**今のシーンでは**そのルールを無視します（例：あえて日の丸構図にしたいとき）。
  無視したルールは「設定」タブの「無視中のルール」に並び、いつでも戻せます。

| モデル | 用途 |

| YOLOX-S 物体検出（80 クラス：人、車、電車、動物、料理…。任意、下記参照） | 被写体（何かまで分かる）。人体ポーズの確認にも使い、草花を人と誤認しない |

| ML Kit 姿勢検出（33 点） | 顔の見えない人物、関節での切れ、全身の判定 |
| ML Kit 被写体セグメンテーション | 汎用の被写体、画面のバランス（Google Play 開発者サービスが必要。初回に自動ダウンロード） |
| 顕著性検出（従来手法、毎フレーム） | 画面で一番「目を引く」ものを被写体に。どんな題材にも有効。画面がすっきりしているかの判定 |
| ML Kit 文字認識（日本語 + 英語） | 看板や標語を被写体候補に。文字の切れ、文字の傾き |

| CLIP + LAION（任意、後述） | 美的評価、シーン、AI 構図 |

## 物体検出モデルのインストール（1 回だけ、推奨）
```bash
python tools/get_detector_model.py
```
YOLOX-S（Megvii、Apache-2.0、約 36MB）を `core/src/main/assets/detector.onnx` にダウンロードし、App を再ビルドします。
- 古い端末で重い場合：`--size tiny`（約 20MB、速いが精度は低め）。より高精度：`--size m`（約 97MB、約 3 倍遅い）
- 入れなくても動作し、ML Kit 物体検出（大まかな 5 分類のみ、車や動物は認識できない）に戻ります
- 検出のしきい値は `coach_config.json` の `detector.min_score`（既定 0.35）

## AI 美的評価モデルのインストール（1 回だけ、PC で）
モデルは約 96MB で、Git リポジトリには含めていません。スクリプトで生成します：
```bash
pip install torch open_clip_torch onnx onnxruntime
python tools/export_clip_model.py
```
スクリプトは CLIP と LAION のヘッドをダウンロードし、ONNX に変換して int8 量子化します（MatMul のみ量子化し、畳み込み層はそのまま。こうしないと Android の ONNX Runtime で動きません）。出力先は `core/src/main/assets/`：
- `clip_image.onnx`（約 96MB）
- `clip_meta.json`

最後に「特徴量の一致度」が表示され、1 に近ければ（> 0.98）変換は正常です。その後アプリを再ビルドしてください。
- より高い精度が必要なら：`python tools/export_clip_model.py --no-quant`（約 350MB、やや遅くなります）
- モデルがなくてもアプリは使えます。AI 美的評価の機能が「未インストール」と表示されるだけです。読み込みに失敗した場合は、「ガイド」タブに原因が表示されます。

### スコアについて
- 美的評価は LAION の基準（おおむね 1〜10）です。ライブビューは低解像度で圧縮されているため、実際の写真よりスコアが低めに出ます。**相対的な高低を見てください**。
- 0〜100 への換算範囲は `AestheticModel.kt` の `NORM_LOW`／`NORM_HIGH` で設定します。実際に撮影してから調整してください。

## 使い方（ソニーカメラ版）
1. a6000：MENU → アプリケーション → **スマートリモコン内蔵**（「スマートフォン転送」ではありません）。
2. スマホをカメラに表示される Wi-Fi（DIRECT-xxxx）に接続。「インターネットに接続されていません」と出たら**接続を維持**を選びます。
3. アプリを開いて「接続」をタップ。
4. 「設定」タブで「レンズの焦点距離」を今使っている焦点距離に合わせます（手ブレの計算に使います）。

### 設定の提案をより正確にするには
- カメラの設定：**ライブビュー表示 → 設定効果反映：入**（ライブビューの明るさが設定を反映するようになります）。
- **ISO を数値で設定**（AUTO にしない）すると、アプリがおすすめの ISO を計算できます。

### 「提案を適用」の制限
a6000 の撮影モードは本体のモードダイヤルで決まり、アプリからは変更できません：
- **絞り**の変更：ダイヤルが A か M
- **シャッター**の変更：ダイヤルが S か M
- **ISO／露出補正**：P／A／S ならたいてい変更可能（M では露出補正を変更できません）

設定できなかった項目は、どのモードに切り替えればよいかアプリが案内します。

## トリミング前提モード（ソニーカメラ版、35-50mm で焦点距離が足りないとき）
**デフォルトは「自動」**：被写体の大きさから、トリミングするかどうかと残す割合をアプリが判断します：
- 人物：顔の高さが仕上がりの約 15% が適切。その他の被写体：仕上がりの面積の約 12% が適切
- 被写体がそれより小さければ、割合に応じてトリミングを想定（最大 50% まで）。風景や被写体がないときはトリミングしません
- トリミングが必要なのに焦点距離が 50mm になっていない場合は、まず「レンズを 50mm 側へ」と案内します（カメラは焦点距離をアプリに伝えないので、ズームした後に「設定」タブで焦点距離を 50 にしてください）
- これらの基準は `coach_config.json` の `autocrop.*` にあり、好みに合わせて調整できます

「設定」タブで「手動」に切り替えて、**残す画面の幅**（80%／70%／60%／50%）と**仕上がりの縦横比**（3:2、4:3、1:1、4:5、16:9）を自分で選ぶこともできます：
- ライブビューに**白枠**（仕上がりの範囲）が表示され、枠の外は暗くなり、三分割線は白枠の中に描かれます
- 構図スコアと移動のヒントは白枠を基準に計算され、白枠が収まり、被写体が白枠の三分割の交点に来ることを目指します
- トリミングは画像を拡大するのと同じです：50mm で 60% を残すと ≈ 83mm（35mm 換算で約 125mm）。安全シャッター速度は実効焦点距離で計算し、ISO 上限も下がります（60% → 1250）
- トリミング後に残る画素数を表示し、8MP を下回ると警告します
- 「AI 構図」は 25 か所を探索し、**最も見栄えの良いトリミング位置**を紫の枠で表示します。撮影後にその枠でトリミングすれば OK です

## スマホカメラ版（app-phone）
同じガイドをスマホ自身のカメラでも使えます。ソニーのカメラは不要です。別のアプリ（「AI構図（スマホ）」）なので、ソニー版と同時にインストールできます。
- 画面構成はソニー版と同じで、ルール、AI 美的評価、AI 構図、方向矢印、自動シャッターも同じです（自動シャッターのスイッチはボタンの行に置き、「ガイド」タブを広く使えるようにしています）
- ライブビューをタップ：そこにピントと露出を合わせます。ズームと露出補正は「設定」タブにあります
- 写真は `Pictures/AiComposer` に保存されます
- スマホは絞りが固定で露出も自動なので、「おすすめ設定／提案を適用」はありません。露出のアドバイスは露出補正の調整を案内します。シャッター速度と ISO はカメラから読み取るので、シャッターと ISO のルールはそのまま使えます。被写界深度のルールは a6000 の APS-C センサー前提のため、自動的にスキップされます

## 写真採点アプリ（app-score）
3 つ目のアプリ「AI写真採点」：撮影済みの写真をスマホで採点します。
- システムの写真選択ツールで選ぶか（ストレージの権限は不要）、アルバムで写真を選んで「共有」→ このアプリ
- 美的評価（約 1〜10）で並べ替え、上位 20% に **★ セレクト**、連写や類似写真に **類似** を表示（PC 用セレクトツールと同じルール）
- 写真を開くと、構図のオーバーレイ、順位、EXIF の撮影設定（シャッター、絞り、ISO、焦点距離）、チェックリスト全体が見られます。**AI 構図** でトリミングの提案（紫の枠）と、その場合のスコアを表示
- アドバイスは「撮影済みの写真」向け：編集でどう直すか、次にどう撮るか

## PC 用セレクトツール
同じ美的評価モデルで、PC 上のフォルダー内の写真をまとめて採点し（JPG とソニー ARW に対応）、連写の類似写真を除いて、良い写真を別のフォルダーにコピーできます：
```bash
python tools/photo_picker/pick_photos.py D:/Photo/2026-11-17 --top 30
```
詳しくは [tools/photo_picker/README.ja.md](tools/photo_picker/README.ja.md) を参照。

## 設定の保存、パフォーマンス監視、テスト
- 焦点距離、トリミング前提、自動シャッターの基準、無視したルールは自動で保存され、次回起動時に復元されます
- パフォーマンス監視：「ガイド」タブに 1 回の分析時間と端末温度を表示。分析が遅いときや端末が熱いときは自動で頻度を下げ（毎秒 4 回 → 2 回 → 1 回）、かなり熱いときは AI 美的評価を一時停止します
- 単体テスト：`core/src/test/` にルール、被写界深度の計算、トリミング、衝突の調整、多言語などのテストがあります。PC で実行でき、スマホは不要です

## よくある質問
| 症状 | 原因／対処 |
|---|---|
| 接続できない | カメラで「スマートリモコン内蔵」が起動していない、またはスマホが自宅の Wi-Fi に戻ってしまった |
| 接続できたが映像が出ない | ヒント欄と「ガイド」タブのメッセージを確認 |
| おすすめ設定の ISO が AUTO になる | カメラの ISO が AUTO です。数値に設定してください |
| 水準器が出ない | 画面内にはっきりした水平線がない（正常） |
| 発熱・電池の消耗 | 分析は毎秒約 4 回で、遅いときや熱いときは自動で頻度を下げます。かなり熱いときは AI 美的評価を一時停止します |
| 「美的評価モデルの読み込みに失敗」と出る | 後ろに原因が表示されます。多くは古いスクリプトで書き出したモデルなので、書き出しスクリプトを再実行してください |
| Gradle 同期がバージョン番号（例：25.0.x）だけ表示して失敗する | Gradle JDK が Java 25 です。JDK 21 に変更してください |
